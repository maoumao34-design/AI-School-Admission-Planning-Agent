# PRD v1 — AI 升学规划 Agent（高考志愿）

> 方向 05 · 决策型 Agent。权威任务说明见 [TASK-SPEC.md](../TASK-SPEC.md)；交付标准见 [DELIVERY-STANDARD.md](../DELIVERY-STANDARD.md)。
> 本 PRD 由 PM 依据 TASK-SPEC + 群内讨论收敛而成；范围/技术栈/用户口径已由 maozh2 于 2026-07-27 确认。

---

## 0. 范围（已锁定）
- 场景：**仅高考志愿**（不做博士/留学）。
- **不含**两项共同工作流（游戏营销 / AI 漫剧）——后续独立处理；最终报告显式标注"范围决策 + 理由"，作为有据取舍。
- 省份/年度/科类：**江苏 2026 · 物理类 + 历史类**（两类都做；maozh2 2026-07-29 锁定）。
- **数据覆盖口径（已锁定，2026-07-29 maozh2）**：两类各 **≥100 所**、**专业组级**（一所多组）、位次**全段连续覆盖**——任意位次段（顶尖到保底）的考生都有冲 / 稳 / 保候选（前 1%/10%/20%/50%/80% 仅为抽检点，**不是只做这 5 档**）；每专业组含 选科要求 / 投档分 / 位次 / 拟招计划 / 学费 / 来源年份；**专业方向（工 / 理 / 医 / 文…）覆盖**（喂专业偏好过滤）。验收以「每档匹配密度 ≥ 8-12 张候选 + 冲稳保齐全」为准。交付节奏：phase-1 每类 ~30-40 所先铺全位次带（解锁每档非空）→ phase-2 加密到 ≥100 所/类 + majors 补全 + 省外热门 + 近 3 年/计划/学费。官方来源可追溯、模拟值标注。
- 三条红线：只规划不承诺录取；官方事实/规则判断/AI建议/个人决定分层；最终以官方页面为准。

## 1. 服务对象（三类，登录 + 多账户 + 数据隔离）
- **学生（考生本人）/ 家长**：1 个考生档案。
- **规划人员（B 方案）**：一个账号管多个考生档案（多客户）；一账号下多条档案相互隔离、支持增删/切换；**不做** 批量/协同/管理后台。
- 三类**共用同一套核心规划流程**（6步/志愿卡/比较/版本），差异只在登录身份 + 账号/档案隔离。

## 2. 核心流程（6 步，必须真实跑通）
对话建条件 → 获取官方信息 → 资格过滤 → 方案比较 → 改条件重算 → 确认导出。

## 3. 核心功能
- **对话建条件**：自然语言说目标，Agent 追问缺失/冲突条件；显示已填条件、缺失项、冲突项。**实现 = 确定性层**（规则抽条件 + 找缺失/冲突 + 决定追问，`/api/condition-building`，已就绪）；maozh2（2026-07-29）决定**不接 LLM key** → 不做 LLM 增强层（红线不变：资格判定永远走确定性规则引擎）。
- **资格校验**：每个候选通过/不通过的规则、原因、官方来源、适用周期；可查规则详情、按资格筛选、跳转原始官方页面复核。
- **候选与方案比较**：结构化志愿卡；筛选/排序/增删候选；并排比较 ≥2 套策略（如院校优先 vs 专业优先）。
- **计划与版本**：后续行动、关键日期、风险提醒、来源更新时间、前后版本差异；改条件重算、确认方案并导出报告。
- **异常处理**：信息不足/无结果/数据过期/来源冲突/需人工复核时，说明原因与下一步。

## 4. 志愿卡字段（示例 · 江苏 2026 物理类 / 历史类）
院校/专业组名称、地区、批次、层次标签（985/211/双一流/公办）、招生代码、可报专业组数、当前位次、**参考概率**（冲刺/稳妥/保底 + 百分比，标注方法与数据年份）、近 3 年计划数/最低分位次/位次差（笔前·笔后）、选科要求、拟招计划、学制与学费、推荐理由（可展开"为什么推荐"）、官方来源 + 更新时间、异常提示。

## 5. 页面（对话区 + 工作区配合）
- 对话区：说明目标、补充信息、修改要求；页面同步显示处理进度、结果依据、下一步。
- 工作区：候选卡列表 / 方案并排比较 / 计划与版本。
- 贯穿：规则与依据可展开查看 + 跳转官方页面；无结果/异常有提示。手机端无明显错位。

## 6. 技术栈（已定）
- **核心**：Next.js(App Router) 一体全栈 + TypeScript + Tailwind + Vercel，**不拆 Python**。
- **规则/概率引擎**：TS 纯函数 + API Routes（可单测、可脚本化驱动 6 步回归）。
- **数据**：JSON（结构化数据集 + 可机读规则表）。
- **对话建条件引擎**：同仓 TS 纯函数（确定性层：规则抽条件 + 追问 + 冲突检测，已就绪）。**LLM 增强层不做**（maozh2 2026-07-29 决定不接 key）；若后续接入，走服务端 env、不碰资格判定。
- **持久化/鉴权（B 增量）**：Supabase Postgres + Supabase Auth + Prisma；RLS 做"账号级 + 档案级"双重隔离。数据模型 `Account → Profile(考生档案) → Plan → Version`。

## 7. MVP 边界
- **做**：一省一年度（江苏 2026 物理类 + 历史类，数据覆盖见 §0）；登录 + 多账户 + 账号/档案隔离；6 步真实跑通；至少真实调用一种数据/规则/模型；改条件后候选与依据随动；手机端无明显错位；可导出报告；官方来源可追溯。
- **不做**：博士/留学；两项共同工作流；规划人员批量/协同/后台；跨省/跨年度；不承诺录取（概率只标注方法 + 年份）。

## 8. 交付物（3 项，缺一不可）
1. **可直接访问网页**（Vercel 部署）：能输入条件、核对官方规则、比较候选、调整条件、输出行动方案。
2. **完整源代码**：README 写清启动/配置/部署、数据来源、资格规则、Agent 流程；模拟功能显式标出。
3. **个人/小组报告**：问题与用户 / 方案与交互 / 实现与技术 / 完成范围与限制 / 测试记录 / AI 协作 / 成员分工。

## 9. 验收要点（对照 DELIVERY-STANDARD）
- 6 步端到端真实跑通（换输入有不同结果，非写死/录像）。
- 至少真实调用一种数据/规则/模型。
- 改条件后候选与依据随动。
- 失败/异常有提示。
- 手机端无明显错位。
- 登录功能 → 多账号数据隔离（含"同账号下不同考生档案数据不串"）。
